The thought I keep coming back to

An AI tutor should not begin with: What answer should I generate?

It should begin with:

What might be happening in this learner’s mind? What evidence supports that belief? What remains uncertain? What is the smallest next action that can both help and clarify?

That is the diagnostic-engine problem.

A fluent conversation is only one loop of tutoring. A student can give the same wrong answer because they do not understand, guessed, rushed, misread notation, forgot something they once knew, copied a procedure, used a valid method the system did not recognise, or received too much help. Those are different states. They should not all produce the same explanation.

current thesis — The engine should not pretend to read a learner’s mind. It should make better decisions under uncertainty, using evidence that can be inspected and corrected.

Prediction is not diagnosis

“This student has a 42% chance of getting the next fractions question right” can be useful. It is still not diagnosis.

Diagnosis means holding more than one explanation at once.

What the system sees What may actually be happening What the tutor should do differently
Wrong answer Missing concept Teach / rebuild representation
Wrong answer Stable misconception Use a contrast case or disconfirming probe
Wrong answer Retrieval failure Give a light cue, then remove it
Wrong answer Careless slip Ask for a quick self-check; do not remediate a whole skill
Wrong answer Misread notation Ask learner to paraphrase the problem
Correct answer Guess / answer-revealing help Do not mark independent mastery
Correct answer Valid alternate route Improve the verifier, not the learner label

I like the idea of a diagnosis as a belief state, not a label.

Target: distributive property
Current belief: probably understood, not established
Candidate misconception: multiplies only the first term
Alternatives: transcription slip / attention lapse
Evidence: same structural error in two unlike problems
Counterevidence: correct verbal explanation yesterday
Confidence: medium
Next action: contrastive symbolic + visual probe

The phrase “weak at algebra” should probably never exist inside a serious tutor. It is too coarse, too sticky, and too easy for a product to start believing its own dashboard.

Every tutoring action is also a measurement

A hint teaches something. It also changes the evidence the tutor will see next.

  • A revealing hint can turn a real misconception into an apparently correct answer.
  • Asking for an explanation can expose reasoning and build metacognition at the same time.
  • Switching to a diagram may teach the concept and reveal that the actual problem was symbolic translation.
  • A delayed retrieval question refreshes memory and updates the estimate of what still remains.

So diagnosis and instruction cannot be cleanly separated in a live tutor.

The next action should have two scores: learning value and information value.

This is a useful product tension. A maximally diagnostic question may feel like an interrogation. A maximally helpful answer may destroy the evidence required to understand the learner. The tutor needs to choose actions that are safe across several plausible learner states.

related: Helpfulness can reduce learning

A diagnostic episode — maybe the minimum useful object

Instead of storing only a mastery number, I think the system needs to preserve a short, replayable diagnostic episode.

objective + relevant prerequisites
raw student work / speech / drawing / answer
normalised evidence claims + capture quality
assistance already used
leading hypotheses + alternatives
models consulted + disagreement
chosen probe / intervention + reason
student response
verification after help
student or teacher dispute, if any

Why this matters:

  • A teacher can see why the system acted.
  • A product team can debug a bad diagnosis.
  • Content teams can discover a broken question, misleading explanation or bad skill tag.
  • The organisation eventually gets a dataset connecting evidence → hypothesis → action → outcome.

This is potentially more valuable than a chat transcript. It is closer to a clinical case record or an engineering incident log.

What the diagnostic engine has to hold at once

1. Domain model

Not just a syllabus list.

  • concepts, procedures and representations
  • prerequisite relations — but marked as expert-authored, empirically inferred, curriculum-mandated or uncertain
  • valid solution paths, not one canonical answer path
  • common misconceptions and bug patterns
  • question / item metadata
  • hints, explanations and interventions
  • curriculum, standard and assessment mappings

The key question is not only, what comes before this concept?

It is:

Which prerequisite, if repaired, is most likely to unlock the greatest downstream learning?

2. Learner model

What the tutor currently believes about this particular learner.

  • mastery by concept and procedure
  • misconception hypotheses, not just errors
  • fluency / retrieval strength
  • confidence and freshness of evidence
  • response to prior interventions
  • access, language and device context when it materially changes interpretation
  • preferences only when they demonstrate value — no permanent “learning style” labels

3. Evidence model

An observation is not self-explanatory.

  • Does this question really test the skill it claims to test?
  • Was the student helped before responding?
  • Is handwriting / speech / OCR reliable enough?
  • Is an explanation independent reasoning, or tutor language repeated back?
  • Are four signals genuinely independent, or four views of the same wrong answer?

4. Decision model

The tutor needs explicit choices:

ask a probe · request explanation · switch representation · hint · teach · repair prerequisite · verify transfer · wait · stop diagnosing · show uncertainty · ask learner/teacher to correct the model · escalate

The four models should be separate. A new handwriting recogniser should not quietly change the meaning of “mastery.” A curriculum editor correcting a prerequisite edge should not require retraining the whole tutor.

Architecture scratch

flowchart TD
  A[Student work, answers, speech, behaviour] --> B[Typed evidence claims]
  B --> C[Diagnostic compiler]
  D[Domain + misconception graphs] --> C
  E[Learner-state estimators] --> C
  C --> F[Probe / teaching / stop / escalation policy]
  F --> G[Tutor interaction]
  G --> A
  C --> H[Student + teacher model view]

The important thing here is that it is a loop, not a pipeline.

observe → normalise → verify → hypothesise → update → choose → intervene → recheck

The LLM belongs inside this loop. It is not the loop.

Knowledge graphs are not enough. We need misconception graphs.

A knowledge graph says what a student may not know.

A misconception graph says what they may believe instead.

Useful misconception-graph edges:

  • produces this wrong-step signature
  • often confused with
  • distinguished by this probe
  • appears in this representation but not another
  • responds to this intervention
  • may be induced by this explanation
  • co-occurs with this other misconception

Example:

“multiplies only first term”
  → error signature: a(b + c) = ab + c
  → contrast probe: 3(x + 4), then explain why 4 is still inside bracket
  → visual: three groups of x + 4 objects
  → near neighbour: adds instead of multiplies
  → verify: new symbolic task + visual transfer

possible moat: The organisation’s map of misconception → evidence → intervention → verified change may eventually matter more than the chat interface.

Research to return to: Kuo, Chen & de la Torre on coexisting skills and misconceptions.

Q-matrix note — boring infrastructure, high-leverage failure point

A Q-matrix maps questions to the skills they require. This is how an answer becomes evidence about concepts rather than just a score.

The risk is obvious once you see it: if a question is tagged to the wrong skills, the tutor can become confidently wrong at scale.

Things I would want in a real product:

  • version every item–skill mapping
  • show whether an expert, data or AI proposed it
  • track what learner data supports or contradicts it
  • make it easy for teachers to dispute it
  • distinguish “tests this skill” from “uses this skill somewhere in the solution”
  • allow multiple valid solution paths

watch: AI can help propose Q-matrices. It should not be allowed to make them invisible or unquestionable. Q-matrix validation work is a reminder that the mapping itself is a model.

Learner-state models — use a portfolio, not a religion

Model / family What it is useful for Why I would keep it What can go wrong
BKT Interpretable online updates Modest data, clear assumptions, works as a baseline Simplifies partial knowledge; often turns work into correct/incorrect
DINA / G-DINA Skill-attribute profiles Explicitly represents combinations of needed skills Depends completely on meaningful attributes and Q-matrix
DKT / AKT / DKVMN Long interaction histories and next-response prediction Can learn temporal patterns and contextual relevance Data hungry; harder to explain; better AUC may not mean better teaching
Graph models Propagation through concepts/items Useful when domain graph is genuinely strong One bad edge can spread a bad inference
LLM + verifier Open-ended reasoning / language / multimodal work Can propose hypotheses and converse Fluent overconfidence; must not silently write the learner model

The near-term answer probably looks like:

Interpretable probabilistic spine + specialised models where they earn their place + LLMs constrained to hypothesis, retrieval and explanation work.

Do not replace BKT merely because something sounds more modern. A simple state model that teachers can inspect may beat an opaque model if the product decision is consequential.

Warm belief updating

The model should not rediagnose from zero after every answer.

But it should not overreact either.

A single careless error should make a small dent. A structural error repeated across unlike problems should make a bigger one. A correct answer after an answer-revealing hint should barely count as independent evidence.

What should change the update size?

  • diagnosticity of the task
  • help already used
  • answer and reasoning agreement
  • recency of prior evidence
  • repeated pattern vs one anomaly
  • same representation vs transfer across representations
  • parser / verifier reliability
  • plausible context: unfamiliar notation, long gap, bad scan, device issue

important: mastery has a shelf life. “Solved independently yesterday” and “solved once six months ago” cannot have the same operational meaning.

The tutor should not erase old learning. It should schedule cheap revalidation as evidence goes stale. Retrieval practice is nice here because it can refresh learning and refresh diagnosis at the same time.

Drift — when the same score stops meaning the same thing

Three kinds:

  1. Individual drift — learner forgets, learns elsewhere, changes effort or context.
  2. Population drift — a new cohort, curriculum, language group or age band arrives.
  3. System drift — question wording, hint policy, content, interface or data capture changes what an observation means.

Useful checks:

  • calibration by cohort, concept, curriculum version, language, device and modality
  • rolling review of high-confidence mistakes
  • shadow evaluation on newly labelled work
  • change detection on input patterns and residual errors
  • conservative fallback to simpler models when new behaviour becomes hard to interpret

The question is not just, when should we retrain?

How will we notice that a 70% mastery score has stopped meaning what it used to mean?

Evidence: fuse claims, not raw signals

An AI tutor can observe answers, steps, handwriting, drawings, speech, code, hint use, edits, time, confidence reports, navigation and teacher comments.

More signals can create more correlated noise.

Every observation should become something like:

Field Example
Claim “Student distributed multiplication over only first term”
Target Distributive property
Direction Supports / contradicts / neutral
Strength High / medium / low diagnosticity
Reliability OCR 0.83; symbolic verifier high
Assistance None / hint / worked example / reveal
Provenance Student writing, verifier, teacher, LLM, timestamp
Dependence New evidence or another view of same response?
Freshness How quickly this should decay

Triangulation is stronger than volume.

wrong final answer
+ same invalid step in working
+ explanation states the invalid rule
+ failure on a contrast probe
= strong misconception evidence

Four UI events from one quiz attempt are not four independent pieces of evidence.

warning: response time is not a motivation detector. Speech hesitation is not an emotion detector. Behavioural traces are interaction evidence, not psychological truth.

Step verification first

For maths, logic, derivations, code and structured writing, the valuable unit is often the first causal error, not the final wrong answer.

The verifier should ask:

  • Does this step follow from the previous state?
  • Is it valid but non-canonical?
  • Where is the first error?
  • Does later work only propagate that earlier error?
  • Is the step incomplete instead of wrong?
  • Did the system fail to recognise a valid method?

Verifier hierarchy:

  1. execution / tests for code
  2. symbolic equivalence and constraint checking for maths
  3. proof-state / logic checking
  4. simulation, units and dimensional checks for quantitative science
  5. rubrics and evidence checks for open-ended work
  6. LLM judgement only when stronger checking is unavailable

The LLM can translate verifier output into a good explanation. It should not overrule a reliable verifier because it speaks more smoothly.

Research note: Daheim et al. on stepwise verification and remediation.

What LLMs should do here — and what they should not

Useful jobs:

  • interpret a student’s natural-language explanation
  • propose multiple misconception hypotheses
  • connect a method to several valid strategies
  • ask small follow-up questions
  • retrieve relevant history and misconception notes
  • make a teacher-readable account of evidence
  • turn structured policy decisions into natural tutoring dialogue

Not useful as an unconstrained role:

“Read this response and tell me what is wrong with the child.”

The stronger pattern:

  1. point to exact evidence
  2. verify correctness with domain tools
  3. generate multiple explanations, including slips and input failures
  4. retrieve from a curated misconception / intervention library
  5. rerank using supporting and contradictory evidence
  6. state what would disconfirm each hypothesis
  7. choose the smallest useful probe
  8. write structured output back into the diagnostic episode

short version: generate → retrieve → rerank → challenge → probe

Research to inspect: MathCog · LLMs still struggle where feedback matters most · Misconception diagnosis from dialogue: generate, retrieve, rerank

LLM memory is not a learner model

Conversation history is long, inconsistent and hard to audit. It should not become the canonical record of a student.

The learner model should live in structured state. The LLM sees a small, task-specific projection of relevant evidence.

Otherwise a casual line like “I’m terrible at geometry” becomes a persistent diagnosis simply because it was memorable language.

Multi-agent diagnosis — useful only if the agents actually disagree for good reasons

Possible roles:

  • evidence agent
  • verifier / first-error agent
  • history agent
  • misconception agent
  • skeptic agent looking for alternatives
  • policy agent choosing action
  • safety / escalation agent
  • narrator for student or teacher

But a committee of differently worded prompts to the same model is not automatically safer. It can be an expensive way of getting the same mistake repeated five times.

Use multiple agents only when they bring genuinely different:

  • tools or verifiers
  • retrieval corpora
  • evidence sources
  • trained models
  • objectives (for example, one agent is rewarded for finding counterevidence)
  • abstention rules

measure: disagreement rate, correlation of errors, and which disagreements lead to teacher correction. Not just final majority vote.

Differential diagnosis: keep alternatives alive

This may be the most important transplant from medicine: not medical content, but the discipline of maintaining a differential diagnosis.

Leading explanation Evidence for What could contradict it Small differentiating probe
Missing prerequisite Fails decomposed substep Solved similar task independently Isolate prerequisite without target procedure
Stable misconception Same structural error repeats None yet Contrast case where false rule predicts a different answer
Retrieval failure Moves after light cue Repeated no-hint failure Delayed no-hint recall
Careless slip Correct explanation + later work Same error recurs Near-transfer task with self-check prompt
Misread notation Verbal interpretation differs Correct notation elsewhere Ask student to paraphrase prompt
Capture error OCR uncertain Same issue in typed work Ask for confirmation of symbol / image

Before acting:

  1. What are the leading explanations?
  2. What evidence would separate them?
  3. What is the cost of acting on the wrong one?

Model disagreement should be classified, not averaged into a fake “63% mastery” number.

Maybe BKT sees high mastery, cognitive diagnosis sees a missing attribute, the verifier sees a valid alternate method, the LLM sees a misconception, and handwriting recognition is uncertain about a minus sign. Those are not five votes on the same question.

Cold start — act while uncertain

The tutor needs a diagnosis to choose a good probe. It needs a good probe to get a diagnosis. That circularity is not an edge case; it is the normal condition.

Early sources of evidence:

  • course and population priors, with provenance
  • prerequisite structure
  • prior assessment data, with consent
  • short adaptive entry task
  • teacher input
  • student self-report treated as weak evidence
  • high-information anchor tasks
  • early prompts chosen to be both useful and diagnostic

The goal is not to finish a perfect placement test before helping. The goal is to choose an early action that is robust across several plausible states.

Example: when the tutor cannot tell a misconception from a slip, ask the learner to compare two worked examples. The activity can help either learner and reveals different things depending on their explanation.

name for this: dual-purpose action — safe instruction + diagnosis.

From CAT to live tutoring

Computerised adaptive testing has an important idea: avoid questions that are too easy or too hard to tell you anything useful.

Useful things to borrow from CAT:

  • calibrated item banks
  • content balancing
  • item exposure controls
  • standard-error-aware stopping
  • clear distinction between assessment and teaching claims

But a tutor has a larger action space.

CAT Ongoing tutor
Hidden state Ability / attributes Rich learner state that changes
Action Ask item Ask, hint, explain, represent differently, wait, escalate
Goal Estimate efficiently Improve future learning while reducing uncertainty
Cost Test length / exposure Effort, trust, time, learning, money, risk

The bridge is expected reduction in uncertainty. CAT asks: which item best localises ability? A tutoring policy asks: which next move helps the learner and tells us what to do after that?

company to inspect: ALEKS and Knowledge Space Theory. Structured assessment can locate learners surprisingly efficiently without a chat interface.

Probe selection

The most valuable generated question may not be a practice question. It may be a question designed to separate two hypotheses.

For example:

Hypothesis A: student does not understand fraction equivalence
Hypothesis B: student understands equivalence but mishandles multiplication

Bad next move: another random fractions question
Better next move: a deliberately designed probe where A and B predict different responses

Generated probes need more checking than generic practice questions:

  • correct
  • aligned to the actual target construct
  • minimally confounded
  • appropriate difficulty and language
  • non-leading
  • not a duplicate of prior evidence
  • safe as both measurement and instruction

open question: Can diagnostic-probe generation become a more valuable content capability than generic question generation?

Stopping is a product decision

How many questions are enough?

Not just a statistical setting. Every additional probe spends time, patience and trust. Every early stop accepts uncertainty.

Possible reasons to stop:

  • leading explanation is clearly separated from alternatives
  • expected information gain is now small
  • next action would be the same across plausible hypotheses
  • cost in effort or frustration is too high
  • a safe teaching action can proceed without more diagnosis
  • uncertainty remains high and the case should escalate

Different decisions need different confidence.

Decision Default evidence bar
Choose between two harmless examples Low
Ask a reversible probe Low
Offer a tentative hint Low–medium
Change next lesson Medium
Mark skill mastered Medium–high + independent evidence
Place in remediation / alert parent High, recent, explainable
High-stakes placement External validation + human governance

Uncertainty is only useful when it changes product behaviour.

Intervention-as-diagnosis

Sometimes the best way to understand a learner is to teach, then observe what changes.

  • Minimal cue works → retrieval failure becomes more plausible.
  • Contrast cases work → overgeneralised rule may have been the issue.
  • Diagram works but symbols do not → representation translation may be the issue.
  • Prerequisite repair unlocks target task → dependency gains support.
  • “Teach it back” exposes whether the repair is generative or merely imitative.

This resembles dynamic assessment: not only what a student can do alone, but what becomes possible with graduated support.

But treatment response is evidence, not proof. One intervention can work for several reasons.

Record:

  • hypothesis before intervention
  • exact intervention components
  • immediate response
  • independent near transfer
  • representation transfer
  • delayed retrieval
  • downstream use
  • whether support was removed

Verification after remediation

A correct answer after help verifies completion, not learning.

Useful verification ladder:

  1. Can the learner immediately reconstruct or explain the corrected idea?
  2. Can they solve a structurally similar problem independently?
  3. Can they recognise it in a different representation?
  4. Can they retrieve it later?
  5. Can they use it inside a more complex task?

I would want the system to use language like:

  • resolved now
  • supported but not independent
  • near transfer shown
  • retained
  • generalised

This is an antidote to one of edtech’s easiest mistakes: optimise immediate post-hint correctness and call it learning.

Diagnose the intervention too

If remediation fails, the student is not automatically the cause.

Maybe:

  • the explanation was poor
  • the representation was mismatched
  • language was inaccessible
  • prerequisite graph was wrong
  • task did not measure what it claimed
  • the verifier misunderstood valid reasoning

Every failed intervention should update beliefs about the learner and the instructional asset.

Confidence, uncertainty and calibrated abstention

Two learners can both be estimated at 60% mastery, but one may have a long history of contradictory evidence and the other may have only one observation. The estimate is the same; the uncertainty is not.

Useful behaviour:

  • broad uncertainty → gather more evidence or choose a robust action
  • narrow uncertainty → personalise more confidently
  • several competing modes → preserve alternatives
  • stale evidence → revalidate before consequential action
  • no reliable small set of explanations → abstain / ask for help

important: an LLM writing “confidence: 0.92” is not calibration. Confidence needs to be checked against labelled outcomes, by task, cohort, modality and consequence.

Things to measure:

  • reliability curves
  • high-confidence error rate
  • calibration by subgroup / content area / modality
  • selective accuracy when the system abstains
  • error at real decision thresholds

Research leads: Conformalized Quantile Regression · uncertainty-aware knowledge tracing

When should a human enter?

Human escalation should be a designed part of the system, not a help button after confidence has already failed.

Escalate when:

  • consequential decision + insufficient confidence
  • models strongly disagree
  • repeated interventions fail
  • student disputes the model and evidence is ambiguous
  • input quality is too poor
  • new misconception has no validated pathway
  • accessibility, wellbeing, safeguarding or integrity issues appear
  • multiple learners show the same issue — maybe the product is wrong

The escalation packet should be short and useful:

what decision is needed
relevant student evidence
leading + alternative explanations
what was already tried
why confidence is low
smallest possible human judgement
way to correct learner model AND domain model

product principle: Teachers are not merely escalation endpoints. They are an input system for improving the diagnostic engine.

An open learner model

The learner model should not become a hidden dossier.

What a student should be able to see:

  • what the system currently believes
  • evidence behind the belief
  • confidence and freshness
  • what will happen because of it
  • ways to say: “I guessed,” “I used help,” “this was a typo,” “I know this another way”

What a teacher should be able to do:

  • inspect evidence trail
  • correct question–skill mappings
  • confirm / reject / defer a misconception hypothesis
  • add relevant context
  • override a path without erasing evidence
  • separate one-student correction from curriculum-wide correction

Corrections should become new evidence, not absolute overwrite.

If a student says, “I knew it; I just made a typo,” the system can believe that a little—but should validate it with a cheap follow-up.

Sources: SMILI: Student Models that Invite the Learner In · Open learner models review

Synthetic students — wind tunnels, not proof

Student simulators can help test policies before testing them on real learners.

Good uses:

  • stress-test probing and stopping rules
  • simulate misconceptions, guessing, forgetting, help-seeking and gaming
  • create regression cases
  • compare policies offline
  • test escalation thresholds
  • estimate latency and infrastructure load

What they cannot do: prove the policy will help real students.

The simulator can become the target. A policy can become excellent at its quirks while failing with real learners.

Validation ladder:

  1. Does the simulator reproduce broad error / transition patterns?
  2. Does it behave plausibly given a specified misconception and history?
  3. Do policies rank similarly in simulation, shadow mode and real data?
  4. Small supervised pilot.
  5. Randomised learning evaluation.
  6. Ongoing mismatch monitoring.

Good line to remember: synthetic students are wind tunnels, not proof that the aircraft is safe to fly.

The AI diagnostic compiler

I like this phrase because it moves the focus away from “one very smart agent.”

The compiler converts one representation into another through explicit, inspectable stages:

raw learner event
→ typed evidence claims
→ candidate hypotheses
→ belief-state update
→ action candidates
→ policy + safety checks
→ tutor action
→ verification evidence
→ revised state

Inputs

  • curriculum / standards
  • concept, prerequisite, Q-matrix and misconception graphs
  • item metadata and difficulty
  • student event history
  • multimodal work
  • teacher and student corrections
  • calibration data and model versions
  • product constraints: time, device, cost, policy, consent

What the internal representation needs to keep

  • provenance
  • assistance / independence level
  • uncertainty and disagreement
  • evidence freshness and dependence
  • candidate actions
  • predicted learning and information effect
  • safety constraints
  • verification requirement

why this might matter: A stable intermediate representation lets the company swap in a better vision model, LLM, bandit policy or knowledge-tracing model without rewriting the tutor from scratch.

The chat model will commoditise faster than this diagnostic infrastructure.

Online path

Fast and conservative:

parse → retrieve state → verify → update belief → choose safe action → log

Offline path

Heavier work:

  • recalibrate models and item difficulty
  • find candidate misconceptions / prerequisite edges
  • detect drift and subgroup failures
  • replay old episodes after a graph correction
  • evaluate policies counterfactually
  • build human review queues

Not every turn needs every model. Routine correctness should go to deterministic graders; ambiguous open-ended work can go to more expensive models; consequential uncertainty can bring extra verification or a human.

Moat?

Easy to copy

  • an LLM that says “I think you misunderstood fractions”
  • generic adaptive difficulty
  • prompt-based Socratic questions
  • a dashboard with red / green skills
  • a multi-agent diagram with no evidence diversity
  • confidence scores that do not control behaviour

Harder to copy

  • versioned domain and misconception graphs that survive curriculum change
  • diagnostic episodes with evidence, alternatives, assistance and outcome
  • validated item–skill mappings
  • high-quality step verifiers in important subjects
  • calibrated cross-model disagreement patterns
  • outcome-linked probe and intervention policies
  • teacher and learner correction data
  • infrastructure for replay, drift detection and experimentation
  • evidence that the diagnosis improves independent transfer, not just next-answer accuracy

The uncomfortable question

Is the moat the diagnostic compiler itself? Or is it the accumulated data created by using it well?

Probably both. The architecture gives the company a place to learn. The real asset is the repeated loop:

evidence → competing diagnosis → targeted action → verified change

Founder-grade experiments

1. Does model disagreement predict bad diagnosis?

Run a probabilistic learner model, verifier and LLM hypothesis model over the same episodes. Check whether disagreement predicts expert correction.

why: disagreement could become a teacher-attention router and a high-value labelling queue.

2. Does generate → retrieve → rerank beat one-shot diagnosis?

Compare one prompt against retrieved misconceptions, reranking and a skeptic pass.

Measure evidence grounding, false confidence and whether the selected probe is useful.

3. Can AI generate contrastive diagnostic probes?

For recurring hypothesis pairs, generate minimal questions where different explanations predict different answers. Validate with experts before student use.

4. Information gain vs learning gain

Compare a policy that reduces uncertainty fastest with one that optimises delayed independent performance, and one that balances both.

5. Intervention-as-diagnosis

For ambiguous cases, compare minimal cue, contrast example, representation switch and prerequisite reminder. Which response patterns update belief and improve transfer?

6. Student correction as a sensor

Let students say “I guessed,” “I used help,” “typo,” or “wrong skill mapping.” Validate disputes with small probes.

7. Diagnostic shelf life

Estimate how quickly evidence decays by concept, representation, independence level and time gap.

8. Diagnose the content

When many learners show the same pattern, test question wording, diagram, parser, Q-matrix and explanation—not only the student.

9. Cross-modal contradiction

Collect cases where final answer, work, spoken explanation and confidence report disagree. The value of multimodality may come more from contradiction than average accuracy.

10. Better diagnosis, same teaching

Hold intervention constant while varying diagnostic quality; then hold diagnosis constant while varying intervention quality. Otherwise every improvement gets attributed to the wrong layer.

Things founders may not notice early enough

  • The tutor can create the misconception it later detects through a leading question or bad hint.
  • A correct answer after answer-revealing help can be negative evidence of independent mastery.
  • “That is not what I meant” may be the most useful signal in the session.
  • Misconceptions may be local errors under pressure, not stable beliefs.
  • Mastery is representation-dependent: symbolic success may hide graphical or verbal failure.
  • Training data is policy-dependent. A tutor that hints quickly produces a different evidence dataset than one that waits.
  • Personalisation can reduce future identifiability by always avoiding the learner’s weak representation.
  • Stopping encodes whose time the company values and what kind of error it accepts.
  • “Low latent ability on factor 17” is statistically interesting and pedagogically useless.
  • The system needs a right to forget as well as a model of forgetting.
  • A naïve model can punish productive experimentation because unusual methods create more visible errors.
  • Teachers are part of the sensor network, not an afterthought.
